# Create an AI Project: Guidelines and Materials for Every Chat

AI compiles guidelines and a list of materials from your chats on one topic, so every new chat in the project already knows them.

## Create an AI Project: Guidelines and Materials for Every Chat

**Difficulty: easy.**\
**Time: about 15 minutes** with a topic you have a few chats about.
## What It’s For

You’ve been preparing a company car tender with AI for three weeks, repeatedly pasting requirements in each chat. On Wednesday, you forget to remind that management rejected leasing, and AI recommends it again in the materials for the director.

A project is a place in the AI tool where all chats on one topic share common guidelines and files, so AI knows what it’s about and what rules apply before you write the first sentence.
## What to Prepare

- a topic you return to with AI at least once a week, for example a monthly newsletter,
- the chat where you did the most work on the topic,
- files you repeatedly upload related to the topic: assignments, spreadsheets, and templates,
- the AI you use at work (where projects exist, shown in the “In your tool” block).
## How to Do It

1. Insert the prompt from the AI exercise at the end of the chat where you did the most work on the topic, or into a new chat with the assignment. AI will write the project name, guidelines, and list of files.
2. Create a project with the AI’s suggested name, insert the guidelines, and upload the files from the list; how to do this is shown in the “In your tool” block. Move older chats on the topic there as well.
3. In the project, open a new chat and ask something definitive, for example, “Why did we exclude leasing?” AI will answer according to the guidelines without you adding anything.
## AI Exercise

Insert this [prompt](glossary:prompt) into the AI you use at work:

I want to create a project for this topic so that every new chat immediately knows what it’s about. Prepare everything I need to insert into the project.

Review this chat and the materials I provide under this assignment. If you can search my previous chats, find other chats on this topic and review them too. At the start, list which chats and materials you are basing your work on.

Then write three things:

1. Project name: short, based on the topic, not today’s task.

2. Project guidelines to insert into its settings. Write them as instructions for AI, no longer than one page:
- What it’s about: goal, audience, and deadline.
- What applies: accepted decisions and what we excluded, with brief reasons.
- How to work: tone, length, format, and rules we repeatedly corrected in chats.
- Materials: which files in the project apply and their purpose.
- As the last line: “If a decision is made or a rule changes in the chat that applies to the whole project, write the new wording of the affected line of these guidelines at the end of your response.”

3. List of files to upload to the project: files attached or mentioned in chats, with one sentence each about their purpose. If multiple versions exist, specify which applies.

Do not include today’s task or things valid only this week in the guidelines. If you can’t tell from the chats what applies or if two places contradict, ask me all questions at once before writing the result. Write the guidelines as a whole so I can insert them at once.

## In Your Tool

### Microsoft Copilot
The closest equivalent to a project in Copilot is a Notebook: on `copilot.cloud.microsoft` in the left panel Notebooks, New Notebook. Upload files from your computer, OneDrive, or SharePoint; insert guidelines via the three dots, Instructions, and Save. Move older chats via the Chats list three dots and Move to notebook.

### ChatGPT
In the left panel, select New project. Insert guidelines via the three dots at the top right and Project settings; upload files on the project page and drag older chats onto the project or choose Move to project. Business and Enterprise plans accept 40 files per project and share it with colleagues via Share.

### Claude
Open Projects in the left panel and create a project with the + button. Insert guidelines via Set project instructions, add files with the + button under project knowledge, and move older chats with Add to project.

### Gemini
The closest equivalent to a project in Gemini is a Gem robot: on `gemini.google.com` open Gem Robots and New Gem. Enter the AI’s suggested name, insert project guidelines into instructions, and if you have a Gem with Custom Instructions, add their text too. Add files in Knowledge via Add files and Save; you can edit guidelines later in My Gem Robots.
## What a Project Is

A [project](glossary:project) has its own guidelines and files that apply only in its chats. [Custom Instructions](card:custom-instructions), i.e., personal instructions in account settings, apply in all chats and include what AI should always know, such as your role or preferred answer length.

Project guidelines cover what applies to the entire topic: goal, rules, accepted decisions, and which file is valid. Today’s task does not belong in the guidelines; you write it in the project chat.
## Keeping Project Guidelines Up to Date

Topics change during work: management makes new decisions, suppliers send new prices. The last line of the prompt guidelines ensures AI writes the new wording of the affected line at the end of such chats. You just replace the old line in the project guidelines.

If your tool has memory enabled, it remembers what was discussed in other project chats. Still put what should always apply into the guidelines because AI selects from memory on its own and might omit something.
## Example

Petra Malá from a company selling office furniture writes a monthly newsletter for corporate customers. News and promotions change; tone, length, and prices excluding VAT remain. At the end of the September chat, she inserts the prompt. AI suggests the name “Newsletter for Corporate Customers” and writes these guidelines:

```text
What it’s about: monthly newsletter for buyers and office managers of companies that buy furniture from us. Published the first Tuesday of the month.
What applies: prices always excluding VAT. Discount codes stopped being used since August, replaced by free shipping over 20,000 CZK.
How to work: three blocks of up to 80 words each, formal address, no exclamation marks. Link to catalog at the end.
Materials: nabidka-podzim-2026.xlsx applies, nabidka-leto-2026.xlsx no longer applies. newsletter-zari.docx is the tone template.
If a decision is made or a rule changes in the chat that applies to the whole project, write the new wording of the affected line of these guidelines at the end of your response.
```

Petra creates the project, uploads the autumn offer and September newsletter, and moves the September and August chats into the project. On October 1, she opens a new chat in the project and writes only “Write the October edition, news is attached.” The October newsletter has prices excluding VAT, three short blocks, and free shipping instead of a discount code, even though Petra wrote nothing about these in the chat.
## If You Get Stuck

- **You don’t see projects in your tool:** In Microsoft Copilot, the closest is Notebook; in Gemini, Gem. The procedure is in the “In your tool” block. In corporate accounts, an admin may disable projects; ask them.
- **AI doesn’t know the assignment in a new chat:** Check the chat is under the project name in the left panel and that you saved the guidelines. If AI still answers incorrectly, ask which line in the guidelines is missing and add it.
- **Files don’t fit into the project:** Free plans accept only a few files per project. Ask AI to summarize older files into one overview or switch to AI that [works directly with a folder on your computer](card:when-chat-is-not-enough).
- **AI mixes in another topic in the project:** In ChatGPT, switch Project settings memory to Project-only memory. Project chats then don’t access memory or chats outside the project.

You have a project with guidelines and files on one topic. In a new chat, you verified AI knows the assignment and what’s decided. The last line of the guidelines ensures AI writes the new wording of the affected line whenever something changes.

## Project / workspace

**What it is:** A workspace where AI can use related conversations, instructions, and materials on a single topic or project over the long term. Exact capabilities depend on the tool.

**What it is not:** It is not automatically an agent nor just a folder with files.

**Why a student needs it:** It helps recognize when a task requires persistent context and shared materials instead of repeatedly inserting everything into a new conversation.

## Prompt

**What it is:** An instruction for a specific interaction with AI.

**What it is not:** It is not the same as long-term context, a stored assistant, or an agent.

**Why the student needs it:** It triggers the exercise and guides its progress; it is not the main learning content.

## Service Outage, Limit, or Overloaded Chat

A common fallback for operational interruptions when working with AI. It is accessible from any card via the **Outage or Exhausted Limit** input. It does not create its own card, check-in, or multiple copies of the same text.

The specific section **When Something Goes Wrong** in the card further addresses errors in input, resources, tools, or procedures. This mechanic triggers when the AI cannot technically continue in the current pass.

## First, distinguish what happened

| What you see | Likely situation | First step |
|---|---|---|
| Tool reports exhausted limit, too many requests, or a reset time | tariff or temporary operational limit | note the reset time and save a return point |
| AI forgets the beginning, refuses additional attachments, or reports input too long | context, file, or task too large | create a handoff and continue in a new context or more suitable environment |
| Tool does not respond, returns a server error, or multiple models fail | service outage | verify official status and choose an approved substitute or pause |

If the AI still responds, it may name the situation itself and prepare a return point. If it does not respond, skip this step. Repeatedly resubmitting the same request will not save the work state.

## Save a return point

Before waiting or switching elsewhere, preserve the smallest package from which you can safely continue:

```text
Goal: ...
What is done and where it is: ...
Confirmed decisions and constraints: ...
Used resources or files: ...
Nearest next step: ...
What should not be changed or recreated: ...
```

If the AI still responds, use:

> Prepare a concise return point for continuing in a new chat or tool. Preserve the goal, completed parts, confirmed decisions, resources, constraints, and one nearest next step. Do not invent anything not present in the conversation.

For longer work, save the return point in the project README or another approved workspace. Sensitive inputs remain only in approved storage.

## Tariff or operational limit reached

1. Find out when the limit resets and whether it applies to the model, function, or entire account.
2. Decide between pausing, reducing scope, or using an approved substitute model or environment.
3. When switching, transfer the return point and only the resources necessary for the next step.
4. Verify that the substitute can handle the required files, tools, and actions. A weaker model may suffice for formatting but fail in analysis or tool use.

## Context, file, or task is too large

1. Have the AI create a handoff before it loses earlier decisions if it still responds.
2. Start a new chat or project with the return point and links to canonical files.
3. Divide work according to meaningful units and preserve shared criteria for the outcome. Randomly splitting text may lose relationships between parts.
4. If the task requires multiple files, bulk work, or project changes, continue via the `when-chat-is-not-enough` card.

## Tool or model outage

1. Verify the provider’s official status. Address account errors only when the service is generally operational.
2. Save the return point outside the currently nonfunctional conversation if it is still accessible.
3. Use an approved substitute tool only if it has the necessary capabilities and the same resources are allowed to enter it.
4. If no suitable substitute exists, pause work and record the exact next step. After restoration, resume from the last confirmed result.

## Safety boundaries

- A limit or outage is not a reason to input work, client, or personal data into an unapproved personal tool.
- A new account, free tier, or different provider may have different data, retention, and training policies.
- Switching between models can change format, accuracy, and available tools. Compare the first output after return with the last confirmed point.
- Do not resend an action that may have occurred before the error until you verify its status. This especially applies to system writes, message sending, purchases, or deletions.

## Returning to the card

After service restoration or switching to a suitable environment:

1. load the return point,
2. show the AI the last confirmed result,
3. request only the nearest next step,
4. complete the original card without repeating finished work,
5. if the tool or model changed, note any difference that may have affected the outcome.

## Record keeping

This mechanic does not create a separate fulfillment. It can only add a return point, chosen path, and any difference after a tool change to the main card’s result.

## Save for Next Time

Optional product mechanic after producing a usable output. It is not a standalone card, has no separate completion, and does not increase the count of completed methods.

## When It Is Offered
- the user has marked the output as usable,
- during work a corrected instruction, style, decision tree, handoff, or other repeatable element was created,
- the same type of work is likely to recur.

The mechanic does not appear for one-off results without transferable parts or where safe saving is unclear.

## What the User Sees
A short option **Save for Next Time** next to the common check-in. Upon opening, AI will suggest:

- what from the result applies repeatedly,
- what will change each time,
- what the user should verify on next use.

The user only confirms or corrects the suggestion. The mechanic does not create an additional mandatory form.

## What AI Creates
The smallest reusable output that corresponds to the actual work:

- a brief personal preference,
- an instruction or prompt,
- a record in Markdown or a second brain,
- a project or assistant update,
- a basis for a skill,
- a change to an existing workflow.

If a suitable artifact already exists, AI updates its current version instead of creating a new copy.

## Where Content Belongs
| Content Type | Default Location |
|---|---|
| Minor personal preference without process steps | memory or profile, if this feature is available and appropriate |
| Canonical instruction, example, or procedure description | Markdown, document, or personal second brain |
| Context limited to one project | project instructions and files |
| Recurring role with stable context | assistant |
| Stable procedure with rules, examples, and templates | skill |
| Several consecutive steps | workflow; when choosing steps and actions, possibly an agent branch |

Memory is not a canonical repository for versioned procedures. It may hold a preference or a link to the current source.

## When the Target Form Is Unclear
The mechanic creates a brief handoff to the card [Create a Project in Your AI Tool](card:asistent). It does not select a form without the user and does not replace a standalone skill card.

## Security and Sharing
- The mechanic uses known approved storage and company policies.
- Specific case data is separated from the stable part.
- Without authorization, it does not write to shared systems or change access.
- Team sharing begins only after repeated use, owner designation, and verification by another person.

## Record Keeping
Information that a reusable artifact was created or changed can be added to the check-in. This is not a separate card completion.
